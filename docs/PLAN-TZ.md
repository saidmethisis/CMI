| Требование | Состояние |
|---|---|
| Ввод текста сразу на 3 языках в одном окне | ✅ **сделано** — вкладки UZ/RU/EN, точка отмечает заполненный язык |
| Продвинутый Rich Text Editor | ⬜ сейчас обычное текстовое поле с Markdown |
| Отдельный стиль для цитат | ⬜ |

**Что делать.**

- **Rich Text Editor.** Форматирование, размеры шрифта, выравнивание, списки,
  ссылки, вставка изображений. Рекомендую Tiptap (ProseMirror): предсказуемый
  HTML на выходе, работает с тремя языковыми вкладками, не тянет лишнего веса.
  Потребуется санитайзер HTML на сервере — иначе редактор становится каналом
  для XSS.
- **Цитаты.** Отдельный блок с фирменным оформлением: вертикальная линия акцентным
  цветом, увеличенный кегль, отступы. Стиль задаётся один раз в `globals.css`.

**Оценка:** 4–5 дней (редактор — основная часть, плюс миграция хранения текста
из Markdown в HTML и санитайзер).

| RSS | ✅ |
| Мгновенный пинг Google Indexing API при публикации | ✅ код готов, нужен ключ сервисного аккаунта |
| Производительность: WebP, lazy loading | ✅ сжатие на клиенте + `next/image` (AVIF/WebP) |
| Минификация JS/CSS | ✅ штатно в Next |
| Реклама без ущерба скорости | 🟡 архитектура есть, кампаний нет |

**Уже сделано сверх ТЗ в этой ветке:**
главная похудела со 177 КБ до 87 КБ, языки вынесены в адрес (`/uz/`, `/en/`) —
без этого узбекская и английская версии для поисковика не существовали, добавлены
hreflang и canonical на каждую страницу.

**Сделано.**

- **Google Indexing API** (`src/lib/indexing.ts`). При одобрении статьи Google
  получает уведомление по всем языковым адресам сразу, при удалении —
  `URL_DELETED`, чтобы читатель не приходил из выдачи на 404. Ключи только из
  переменной окружения; нет ключей — публикация работает как прежде.
- **Person в разметке.** Страница автора отдаёт `ProfilePage` + `Person`
  (должность, биография, специализация, ссылки на профили) и список его статей.
  В разметке статьи автор теперь ссылка на этот профиль, а не строка имени.
- **OG-картинка.** Карточка 1200×630 рисуется на лету: `/og` для сайта,
  `/og/article/<slug>` — для статьи без обложки. Заголовок, рубрика, автор, дата.
  Шрифт с кириллицей лежит в репозитории: встроенный в генератор знает только
  латиницу, и русские заголовки выходили пустыми прямоугольниками.
- **`next/image`.** 12 мест переведены на компонент `Cover`: свои файлы идут через
  оптимизатор (AVIF/WebP, размер под экран, кэш сутки), чужие ссылки — обычным
  тегом. Так один автор со ссылкой на неизвестный домен не уронит страницу.

**Осталось на вашей стороне:** ключ сервисного аккаунта Google (см. `.env.example`,
раздел «Мгновенная индексация») и подтверждение прав на домен в Search Console.

> **Замечание про Windows.** Генератор картинок в поставке Next не запускается на
> Windows (ошибка в путях внутри самого пакета). На этой машине `/og` отвечает 404
> и пишет причину в лог; на сервере Linux, где работает сайт, карточка рисуется.
> Отрисовку проверял отдельно — русский, узбекский и английский заголовки выводятся
> верно.

## Блок 5. Биржевые данные (запрос сверх ТЗ) ✅

Блок «Respublika fond bozori» — как на vaqt.uz: карточки эмитентов с ценой
закрытия, ценой последней сделки и её датой.

**Источник:** `api.parse.bot/scraper/17b8ba45-…/get_stock_quotes` (Tashkent Stock
Exchange, uzse.uz).

**Важно:** API платный, авторизация заголовком `X-API-Key`, списывает 2 кредита за
вызов. Без ключа возвращает `401 Missing X-API-Key header` — проверено.

**Сделано.**

- `src/lib/stock.ts` — по образцу `bank-rates.ts`: кэш на сервере 15 минут (один
  запрос на весь сайт, а не на каждого читателя — иначе кредиты сгорят за часы),
  ключ только из `PARSE_API_KEY`, таймаут 12 секунд, при недоступности отдаётся
  последний удачный снимок.
- `src/app/api/stock/route.ts` — публичный JSON для клиентского обновления.
- `src/components/StockBoard.tsx` — карусель карточек, серверный рендер, ссылка на
  источник, время обновления, знак изменения в процентах.
- Место на главной: под курсами банков, прямо над лентой.
- Переводы: RU/EN/UZ, узбекские подписи — как на vaqt.uz («Respublika fond bozori»,
  «Yopilish narxi», «Oxirgi bitim narxi», «Oxirgi bitim sanasi»).

**Осталось на вашей стороне:** прислать `PARSE_API_KEY`. Без ключа блок просто не
показывается — выдуманных котировок на сайте не будет.

**Проверено:** разбор ответа устойчив к разным именам полей (snake_case, camelCase,
узбекские) и к обёрткам `{data:[…]}` / `{results:[…]}`; отсутствие цены даёт «—», а
не «0.00»; при неизвестной форме ответа блок скрывается.

## Вопросы, которые нужно решить до начала

1. **Ключ `PARSE_API_KEY`** — без него биржевой блок не заработает. Пришлите ключ
   или один пример ответа `get_stock_quotes`, чтобы зафиксировать имена полей.

   обновления: раз в 15 минут — это ~2 900 кредитов в месяц, раз в час — ~1 450.
3. **Табло полётов** — источник не назван. Есть ли договорённость с аэропортом или
   берём открытые данные?
4. **Каталог компаний** — что показывать в карточке и кто наполняет: редакция или
   сами компании через кабинет?
5. **Гамбургер-меню** — куда девать рубрики и вход в кабинеты после его удаления
   (мой вариант выше).
6. **Favicon** — нужен файл от вас. OG-картинка больше не нужна: рисуется сама.
